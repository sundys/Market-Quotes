# Market-Quotes 极简行情 App

打开即看、一眼知道涨跌的极简金融行情 App：

- 国际黄金（COMEX 期金，USD/盎司）
- 纳斯达克 100（100.NDX）
- 标普 500（100.SPX）
- 道琼斯（100.DJIA）
- 上海黄金 Au99.99（元/克）

第一阶段只有行情展示：当前价格、涨跌额、涨跌幅、极简迷你走势图。无交易、无资讯、无账户。

## 架构

```text
akshare 生态（全部国内数据源，无 Yahoo）
    ├── 东方财富：美股三大指数实时（一次请求）与 K 线
    ├── 新浪外盘：COMEX 黄金期货实时（一次请求）与日线
    ├── 上海黄金交易所：Au99.99 实时（一次请求拿全量）与日线
    ├── 内存缓存 + 磁盘 JSON 快照
    └── 后台采集器（统一调度、抖动、超时<间隔、退避冷却、三源互相隔离）
```

> 已彻底移除 Yahoo Finance 数据源（其 429 限流长期不稳定）。

## 启动后端

```bash
cd server
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

- 首页数据：`GET /api/market/overview`
- 详情走势：`GET /api/market/{id}/history?period=1d|1w|1m|6m|1y`（天/周/月/半年/年；SGE 当日走势为后端累积采样点）
- 健康检查/监控：`GET /health`（含 429 计数、缓存命中、最后成功时间）

环境变量见 `server/.env.example`（采集间隔、退避参数、缓存 TTL 等）。

## 运行 App

```bash
cd app
```

## 稳定性设计（对应 AGENTS.md 第 6/7/9/20 节）

- **缓存优先**：App 打开先读本地最近数据，后台请求后端更新；后端一级内存缓存 + 二级磁盘快照（写盘节流）。
- **每源一次请求**：指数 1 次批量请求、期金 1 次、SGE 1 次；SGE 日线（涨跌基准/月线/详情历史）共用一份 1 小时 TTL 缓存。正常交易时段约 320 次/小时，全部由后端发起，与 App 用户数无关。
- **低频采集**：指数 45s、期金/SGE 30s 一次（可配置），休市自动降频到 5 分钟。
- **三源隔离**：东财（指数）/ 新浪外盘（期金）/ SGE 各自独立的健康状态、退避冷却与请求锁；实时采集与 K 线历史用不同锁，互不阻塞。任一源失败只标记对应行情 stale。
- **调度健壮性**：单次抓取超时始终小于采集间隔；上一轮仍在飞时本轮只跳过（不记失败、不进冷却）；间隔带 ±10% 抖动，避免固定相位尖峰。
- **429/限流处理**：指数退避（5s 起、上限 120s）+ 随机抖动；持续失败进入冷却，暂停主动请求，期间继续返回缓存。
- **stale 标识**：请求失败、批量响应缺项、或交易中数据长时间不更新（>3 倍刷新间隔）都会标记 stale，UI 显示“部分数据可能延迟 / 更新于 HH:mm”，不伪装实时。
- **开闭市**：按市场时区与节假日表计算交易状态（美股、COMEX、SGE 各自规则），UI 显示“交易中 / 已收盘”。
- **测试降级**：设置 `YF_FORCE_429=1` 启动后端即可模拟全部外部源失败，验证退避/冷却/降级。

## 已知行为说明

- 所有行情数据来自国内源（东财/新浪/上金所），无 Yahoo 依赖；若东财接口异常，指数卡片显示 `--`，黄金数据不受影响，恢复后自动重新采集。
- 国际黄金为 COMEX 黄金期货（Globex 时段，每日 17:00-18:00 ET 维护），UI 已明确标注“期货”；与伦敦现货存在正常价差。
- SGE 一次请求即可拿到现价、今开、最高、最低、行情时间与当日分钟序列；涨跌幅基于最近交易日收盘价计算（基准持久化在磁盘缓存，跨日自动刷新）。
- SGE 当日分钟序列只保留最近一次响应（不落盘）；详情页“天”走势仍为后端累积采样，进程重启后重新累积。
